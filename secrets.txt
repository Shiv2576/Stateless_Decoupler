📌 The Problem: WordPress Can't Scale
1. WordPress saves session data locally
By default, WordPress stores user session information (login status, shopping cart, etc.) as files on the local disk of the specific server/pod that handled the request.

2. This breaks horizontal scaling
When you have multiple pods (e.g., Pod 1, Pod 2, Pod 3), a user might log in through Pod 1, but their next request could be routed to Pod 2. Pod 2 has no access to the session file saved on Pod 1's local disk.

3. Result: Broken user experience
The user appears "logged out" or loses their session state randomly. Load balancing becomes impossible because each pod can only serve users whose session data it has locally.

4. The Solution: Move sessions to Redis
The project configures WordPress to use Redis as a central session store (session.save_handler = redis in wp-config.php). Redis acts as a shared database that all pods can access.

5. This is the "Decoupler"
Any pod can now serve any user request because session data is decoupled from individual app servers. This enables true horizontal scaling — just add more pods and they all share the same session state via Redis.
